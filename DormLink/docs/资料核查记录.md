# 鸿蒙技术资料核查记录（供个人报告引用）

核查日期：2026-11-11（只记录实际可追溯的公开文档，项目未做真机实验）。

## 技术问题一：Preferences 写入后，结束应用进程能否读取？

**官方资料A**：华为开发者《持久化用户首选项数据（ArkTS）》：https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/data-persistence-by-preferences/  
主要结论：Preferences 适用于轻量KV数据；修改数据后须 flush 落盘；数据存在应用沙箱；默认XML存储，从API18增加GSKV；不适合敏感数据。

**官方资料B**：华为开发者《@ohos.data.preferences（用户首选项）》（API14）：https://developer.huawei.com/consumer/cn/doc/harmonyos-references-V14/js-apis-data-preferences-V14/  
主要结论：`getPreferencesSync` / `putSync` 是 API10+ 可用的接口，`flush()` 异步落盘；`flushSync()` 需 API14，因此工程目标 API12 选择 `flush()`。不支持多进程并发写 Preferences。

**判断**：业务状态字段多，但实际只有一个轻量 Snapshot；用 JSON 字符串作为 KV 值比 RDB 简洁。每次保存后 await flush，在进程死亡前确保持久化完成。对于大规模日志、复杂查询、敏感数据，不建议 Preferences，未来可迁移 RDB；**恢复效果仍须在设备中实测**。

## 技术问题二：单元测试如何核验真实业务函数？

**官方资料C**：华为开发者《单元测试框架/自动化测试框架使用指导》：https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/unittest-guidelines/  
主要结论：Hypium 提供 `describe`、`it`、`expect`、断言和Mock能力；官方示例包含 `@ohos/hypium` 1.0.25。

**官方资料D**：华为开发者《创建和运行测试用例》：https://developer.huawei.com/consumer/en/doc/harmonyos-guides/ide-instrument-test/  
主要结论：DevEco Studio 可运行本地测试和设备测试；测试类命名要求 .test.ets；测试运行结果必须在 IDE 中保存证据。

**判断**：规则判断与UI分离，避免单元测试依赖设备UI状态。12条直接断言 RuleEngine 的输出，测试项同时覆盖正常、边界和异常。Node/TS移植测试只可作为逻辑预检，不等于 DevEco/Hypium 通过。

## 学习计划

1. 比较 API12 的 Preferences 与 API14+ `flushSync`、API18+ GSKV，在两个 SDK 版本分别建立测试工程，记录 API 支持、迁移代价与失败模式。
2. 每次 SDK 更新前先查看官方文档的“起始 API 版本”字段，结合IDE类型提示确定调用方式；再执行自动化用例和杀进程恢复回归。
3. 如超过1000条日志或需要按日期筛选，阅读官方 RDB 指南并实现异步分批查询，对比查询时间与存储容量。
